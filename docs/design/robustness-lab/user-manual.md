# 鲁棒性实验室新手使用说明书

## 为什么需要鲁棒性实验

水印写入成功，只能说明它在刚生成的图片中可以恢复。现实中的图片可能被 JPEG 压缩、加噪、模糊、缩放、裁剪或调色。鲁棒性实验室用可重复的受控实验回答：经过哪些处理、处理到什么程度后，当前水印开始恢复失败。

这里的“鲁棒”表示经受变化后仍能工作，不表示永远无法移除。

## 先认识实验中的角色

- **载体**：用来写入水印的原始图片。
- **Payload**：准备写入并在最后核对的文本。
- **Profile**：隐蔽、均衡或鲁棒三种水印配置。
- **扰动步骤**：对图片进行的一次处理，例如压缩或模糊。
- **扰动链**：多个步骤按列表从上到下依次执行。
- **扫描**：让某一个参数从较轻逐渐变化到较重。
- **trial**：相同强度下重复实验的次数，用来观察带随机性的处理。
- **种子**：控制实验随机数；相同条件和种子便于复现。

## 第一次实验建议

第一次不要建立很长的链，也不要同时研究多个变化。建议准备一张有权处理、尺寸适中且纹理丰富的图片，Payload 使用一句短文字，只选择“均衡”Profile。

1. 打开“鲁棒性实验室”，选择原始载体。
2. 输入短文本 Payload；第一次可以不设密码。
3. 只选“均衡”Profile。
4. 添加一个 JPEG 扰动步骤。
5. 在界面支持的范围内，为 JPEG 的 `quality` 设置一个从高到低的单参数扫描。质量越低，通常压缩越强。
6. trial 先设置为 1；涉及随机噪声时再增加次数。
7. 设置并记下实验种子。
8. 点击“预检”。只有预检通过后再点击“运行”。

预检会在读取和处理图片前检查参数是否合法、总案例数是否过多。它能避免明显错误和意外的大实验，但不保证实验一定成功。

## 为什么要先建立未扰动基线

运行开始后，系统会先在“不加任何扰动”的条件下写入并提取水印。如果这一步都失败，后续失败就不能归因于 JPEG、噪声或模糊，因此实验会停止。这叫基线检查，是让结论可信的第一步。

## 怎样读结果

- **成功率曲线**：横向通常是扫描参数，纵向是多次 trial 中成功恢复的比例。
- **Profile 矩阵**：比较不同 Profile 在不同强度下的结果。
- **首次失败**：扰动链逐步执行时，第一次观察到失败的位置。它说明“到这个前缀时失败了”，不等于最后那个步骤单独就是唯一原因。
- **恢复后再次成功**：后续处理偶尔可能让信号重新可读，系统会标记 `RecoveredAfterFailure`，不会把链简单描述成永远单调变差。
- **N/A/SizeMismatch**：尺寸变化后某些全参考质量指标无法直接计算，不会用 0 冒充结果。

初次使用时，先关注“能否完整恢复”和成功率。BER、置信度、RS 修复数属于诊断信息，可在需要定位原因时再看。

## BER 的直观含义

数字信息由 0 和 1 组成。BER 是读错的 bit 占全部 bit 的比例。`PhysicalRawBer` 观察每个实际副本在投票前的错误；`VotedPreEccBer` 观察副本投票后、纠错前的错误。即使最终成功，前面也可能已有错误，只是被投票或纠错修复了。

## 怎样设计更可信的实验

- 一次只扫描一个参数，其他条件固定。
- 先用单步骤找到大致边界，再添加多步骤链。
- 对随机噪声增加 trial 数，不要用一次偶然结果下结论。
- 比较 Profile 时保持载体、Payload、配方、扫描范围和种子一致。
- 导出 JSON 保存完整结构化结果；CSV 适合在表格软件中查看案例。
- 报告结论时写明图片、Profile、扰动顺序、参数范围、trial、种子和实现版本。

## 隐私与保存

Payload、密码、像素和结果不会进入 Document 快照；恢复工作区后需要重新输入并再次运行。导出的 JSON/CSV 不写入 Payload 内容、密码、绝对路径或密钥，但仍可能包含图片文件名和实验参数，分享前应检查业务敏感性。

## 不要从一次实验推出什么

- 不能推出水印对所有图片都同样可靠。
- 不能推出某个平台或编码器一定产生相同结果。
- 不能把“当前样本通过”写成“不可破坏”。
- 不能把 JPEG、缩放和裁剪混在一条复杂链后，直接断言其中某一步是唯一原因。

需要参数 ID、严格指标和报告边界时阅读 [使用指南](guide.md)；想理解扫描、概率、BER 和质量指标时阅读 [数学原理](mathematical-principles.md)。
